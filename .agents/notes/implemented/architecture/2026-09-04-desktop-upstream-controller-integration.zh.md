# Agent Note: 桌面扩展遵循上游控制器的职责归属

Status: implemented

[English](2026-09-04-desktop-upstream-controller-integration.md) | 中文

## 问题

桌面扩展与上游共用 API 和客户端包。控制器重组后若保留已删除的 API 代理或仅含依赖的示例，就会让桌面端额外维护一套实现，并可能使安装包遗漏插件。

## 决策

会话控制器将提供方品牌图标投影到模型目录。Models 设置 store 合并活跃提供方注册表与可配置提供方时保留这些图标。生成的 Remote 校验器从这些职责所属类型派生，不使用桌面专属 schema。插件清单保留上游预设分组，以及桌面端的 profile 移除和 CLI 安装操作。

Electron 通过持续维护的 `dsh-python-runtime-closure` 清单暂存正式 CLI，清单提供动态加载的 profile 插件及其必需的 peer 依赖。两种桌面壳都会保留 Host 输出的完整认证环回 URL。桌面 CI 和开发流程设置 `DSH_CLIENT_TITLE`；布局与侧栏使用该公开构建值，并保留上游版本徽标和本地化通用回退名称。原生关闭、重新打开、单实例和显式退出行为仍归 Electron 主进程所有。

不保留无消费者的 directory-flow 包：工作区 UI 拥有实际使用的目录选择槽位。独立包不能在没有消费者时重复声明相同槽位。

私有 Electron 暂存清单属于桌面安装包发布序列，不属于上游 npm 发布族。它必须保持私有，且不能依赖实验性插件。Models 设置在自己的 locale 模块中维护品牌选项名称；共享图标原语只负责资源渲染。插件安装文案也来自设置语言词典。

## 考虑过的替代方案

保留已删除的 API 代理和示例清单可以维持文件位置，但会重复上游职责并允许依赖漂移。所有冲突都采用上游内容则会丢失桌面元数据和管理操作。本集成保留上游当前的职责划分，将桌面扩展迁入对应实现。

## 后果

合并上游需要进行行为检查，不能只移除冲突标记。目录、设置和清单测试覆盖保留的元数据及操作；组装后的浏览器测试与隔离的原生窗口测试覆盖安装入口。运行时冒烟测试使用临时 `DSH_HOME` 目录，不声称兼容旧版用户数据格式。Linux 与两种 macOS 架构仍由独立 CI 验证。
