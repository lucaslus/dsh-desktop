# Agent Note: 桌面窗口关闭与应用退出分离

Status: implemented

[English](2026-09-04-desktop-window-close-lifetime.md) | 中文

## 问题

关闭桌面窗口会终止由应用持有的 Harness 宿主，用户只想收起窗口时也会中断工作。如果应用留在后台却没有重新打开的入口，用户同样无法回到工作现场。

## 决策

[Electron 应用](../../../../apps/electron/README.zh.md)在普通关闭时隐藏窗口，保留渲染进程和宿主。Dock 激活和再次启动会显示并聚焦该窗口；若已最小化，则先恢复。单实例锁阻止第二次启动创建重复宿主。显式 Quit 允许销毁窗口，并执行宿主清理。就绪状态由应用持有，因此即使就绪消息到达时没有窗口，替代窗口也能加载已有宿主。

[原生 macOS 壳](../../../../apps/desktop/README.zh.md)在关闭后保留 AppKit 窗口和 Web 视图，通过应用委托重新打开，并且只在应用终止时结束宿主。两种壳都将 Close Window 与 Quit 分开提供。

本决策涉及窗口生命周期，不改变独立的[源码安装](../feature/2026-08-14-desktop-source-installation.zh.md)和 [Electron 分发](../feature/2026-08-31-fedora-electron-rpm-distribution.zh.md)决策；这些记录仍保留安装及打包方面的依据。

## 考虑过的替代方案

**每次关闭都销毁渲染进程。** 只保留宿主能降低空闲内存占用，但会丢失未发送输入和渲染进程中的局部状态。保留窗口无需增加状态序列化即可保存两者。

**只保留应用，不处理激活。** 仅移除自动 Quit 会让隐藏的应用难以重新打开，再次启动时还可能产生重复宿主，尤其在 macOS 以外的平台。

## 影响

收起窗口不会取消正在执行的任务。保留的渲染进程会持续占用内存，直到显式 Quit；Linux 用户在窗口不可见时通过应用启动器重新打开。本改动不引入系统托盘或后台调度服务。

macOS 和 Linux 定向单元测试覆盖启动中关闭、无窗口时宿主就绪、激活、从最小化恢复、单实例拒绝和显式 Quit。原生 Electron 快照通过实际应用入口与真实暂存宿主，在无需模型密钥的情况下验证隐藏期间启动、Close Window 菜单、第二进程唤回和宿主关闭。CI 在 macOS 和 Linux 的两种架构上运行原生快照，Linux 使用 Xvfb。原生 Swift 编译检查委托 API；Swift 壳的 macOS Dock 交互和 Fedora 窗口管理器行为仍需手动验证。

快照观察原生菜单的 `close` 请求和应用的 `second-instance` 事件，再断言窗口可见状态与宿主可访问性。在 macOS 上，Electron 根据 AppKit 遮挡状态变化产生 `show` 和 `hide` 通知；快速切换时这些通知可能被合并，导致窗口已经隐藏后，仅等待事件的测试仍未结束。桌面应用分支 CI 会在创建标签前覆盖两种 macOS 架构，快照超时会报告正在等待的操作和原生窗口状态。
